# Textlume 优化路线图

> 目标：在保持轻量、启动快和界面简洁的前提下，逐步补齐 Notepad++ 与 Windows 记事本中高频、可靠的编辑体验。
>
> 建立日期：2026-09-20
>
> 执行方式：按优先级逐项实现，每完成一项都进行构建和场景验证。

## 一、当前未保存文件保护现状

- 编辑中的文档停止输入约 1 秒后自动保存恢复草稿，连续输入时每 5 秒扫描一次作为兜底。
- 恢复草稿存储在 `%APPDATA%\textlume\recovery`，不是临时目录。
- 应用崩溃或电脑重启后，启动时会自动恢复草稿。
- 手动保存文件后会删除对应草稿。
- 手动关闭未保存标签时会提示“保存 / 不保存 / 取消”。
- 自动保存使用临时文件写入并原子替换 JSON 文件；启动恢复时跳过损坏草稿并记录诊断日志。
- 因此当前方案整体可恢复，输入停止后约 1 秒即可落盘。

## 二、第一阶段：未保存内容保护

### 1. 缩短自动保存窗口

- [x] 改为内容变更后约 1 秒进行防抖保存。
- [x] 保留定时保存作为兜底机制。
- [x] 避免每次按键都触发磁盘写入。

验收标准：输入内容后应用在短时间内被强制结束，重启后能恢复最近内容。

### 2. 原子写入恢复草稿

- [x] 先写入临时文件。
- [x] 写入成功后再替换正式草稿文件。
- [x] 启动恢复时忽略损坏草稿，并保留可诊断信息。

验收标准：模拟写入中断时，不会得到空草稿或半截 JSON。

### 3. 关闭未保存标签时增加确认

- [x] 未保存文档关闭时弹出确认对话框。
- [x] 提供“保存 / 不保存 / 取消”。
- [x] 对已保存且无改动的文档保持直接关闭。
- [x] 关闭窗口时统一检查所有未保存文档。

验收标准：用户不会因为误点关闭按钮而无提示丢失未保存内容。

### 4. 关闭窗口前保存恢复草稿

- [x] 窗口真正退出前等待当前恢复草稿写入完成。
- [x] 关闭程序时不阻塞未保存内容，重启后继续显示恢复草稿。
- [x] 强制刷新尚未达到 1 秒防抖时间的最新编辑内容。
- [x] 写入完成后再继续“保存 / 不保存 / 取消”关闭流程。

验收标准：刚刚输入的内容不会因为立即关闭窗口而落在防抖保存窗口之外。

### 5. 完善会话恢复信息

- [x] 保存并恢复当前活动标签。
- [x] 保存光标位置、滚动位置、选区、编码、行尾和语言模式。
- [x] 兼容旧版本仅保存文件路径的会话数据。

验收标准：重启后恢复打开文件、活动标签及上次编辑视图状态。

### 6. 外部文件变化检测

- [x] 定期检查已打开文件的修改时间、大小和只读状态。
- [x] 外部修改后提供“重新加载 / 保留当前内容 / 对比”。
- [x] 重新加载后清除脏状态，保留当前内容时标记为未保存。

验收标准：外部程序修改文件后，编辑器不会静默覆盖或丢弃当前内容。

## 三、第二阶段：标签页和会话体验

- [x] 保存并恢复当前活动标签。
- [x] 保存光标位置、滚动位置、选区、编码和语言模式。
- [x] 支持拖拽调整标签顺序。
- [x] 支持 `Ctrl+Shift+T` 重新打开已关闭标签。
- [x] 标签悬停显示完整路径。
- [x] 支持固定标签和按最近使用顺序切换标签。

## 四、第三阶段：编辑效率

- [x] `Ctrl+G` 跳转到行号和列号。
- [x] 行书签、上一个书签、下一个书签。
- [x] 矩形选择和多光标编辑。
- [x] 函数 / 类 / 符号列表。
- [x] 更完整的语言自动补全和代码片段。
- [x] 查找和替换历史记录。
- [x] 宏录制与回放。

## 五、第四阶段：文件可靠性和工程质量

- [x] 检测外部文件修改，并提供重新加载、保留或对比选项。
- [x] 完善文件被删除、重命名和只读状态的提示。
- [x] 从其他实例打开文件时唤起并聚焦已有窗口。
- [x] 合并重复的文件打开逻辑。
- [x] 增加编码、保存、恢复和单实例逻辑测试。
- [x] 将单实例实现改为更可靠的 Windows 命名互斥锁或 Tauri 官方方案。
- [x] Windows 文件关联仅注册普通文本类型（txt/md/markdown/log/csv/json）；代码、网页等文件仍支持应用内打开，但不主动注册系统默认关联。

## 六、当前实施顺序

1. 缩短自动保存窗口。
2. 原子写入恢复草稿。
3. 关闭未保存标签确认。
4. 关闭窗口前保存恢复草稿。
5. 完善会话恢复信息。
6. 外部文件变化检测。
7. 标签页增强和编辑效率功能。
